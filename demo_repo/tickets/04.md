# SHOP-04 — Free-shipping threshold checked against pre-discount subtotal

**Type:** Bug  
**Priority:** High  
**Component:** `shop/order.py`, `shop/shipping.py`  
**Affects:** `Order.compute()`, `compute_shipping()`  
**Failing test:** `demo_repo/tests/test_order.py::test_order_shipping_based_on_amount_paid_not_subtotal`

---

## Summary

The free-shipping eligibility check compares `cart.subtotal()` (the raw,
pre-discount, pre-coupon price) against the `FREE_SHIPPING_THRESHOLD` instead of
the **amount the customer actually pays** (after discount and coupon).  This means
a heavily-discounted order can qualify for free shipping even though the customer
only pays a small amount, and conversely an order that starts below the threshold
but qualifies after discounts is still charged shipping incorrectly.

## Business Rule

> Shipping is free when **the amount the customer pays** (after all discounts and
> coupons) is at or above `FREE_SHIPPING_THRESHOLD` ($75.00).

## Steps to Reproduce

```python
from shop.cart import Cart
from shop.order import Order
from shop.shipping import FLAT_RATE

cart = Cart()
cart.add_item("ITEM", 160.00, 1)          # subtotal = 160.00 (≥ $75 — raw)
summary = Order(cart, coupon_amount=70.00).compute()
# 10 % tier → 144.00 − 70 coupon → customer pays 74.00  (< $75)

print(summary.after_discount)  # → 74.00  (correct)
print(summary.shipping)        # → 0.00   (wrong — should be 5.99)
```

## Expected Behavior

A customer who ends up paying $74.00 must be charged the flat shipping rate
(`FLAT_RATE = $5.99`), because $74.00 < `FREE_SHIPPING_THRESHOLD` ($75.00).

```python
summary.shipping == 5.99
```

## Actual Behavior

Shipping is `0.00` because the threshold is checked against the pre-discount
subtotal ($160.00 ≥ $75.00), granting unearned free shipping.

## Root Cause

The bug requires fixes in **two files**:

### 1. `shop/order.py` — wrong value passed to `compute_shipping()`

```python
# current (buggy) — passes pre-discount subtotal
shipping = compute_shipping(subtotal)

# correct — pass the amount the customer actually pays
shipping = compute_shipping(after_discount)
```

### 2. `shop/shipping.py` — parameter name is misleading

The parameter is named `cart_subtotal`, which implies (and in fact receives) the
raw cart total.  Rename it to `amount_paid` to correctly express the intent and
prevent future callers from passing the wrong value:

```python
# current
def compute_shipping(cart_subtotal: float) -> float:
    if cart_subtotal >= FREE_SHIPPING_THRESHOLD:

# correct
def compute_shipping(amount_paid: float) -> float:
    if amount_paid >= FREE_SHIPPING_THRESHOLD:
```

## Files to Change

| File | Change |
|---|---|
| `shop/order.py` | Pass `after_discount` instead of `subtotal` to `compute_shipping()` |
| `shop/shipping.py` | Rename parameter `cart_subtotal` → `amount_paid` |

> The shipping unit tests in `test_shipping.py` already pass the correct
> `amount_paid` value directly, so no test changes are needed.
