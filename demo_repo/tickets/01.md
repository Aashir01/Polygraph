# SHOP-01 — Ghost line item remains in cart after full quantity removal

**Type:** Bug  
**Priority:** Medium  
**Component:** `shop/cart.py`  
**Affects:** `Cart.remove_item()`  
**Failing test:** `demo_repo/tests/test_cart.py::test_remove_item_all_units_removes_line`

---

## Summary

When `Cart.remove_item()` is called with a quantity equal to (or greater than) the
current stock of that SKU, the line item is not deleted from the internal dictionary.
A `LineItem` with `quantity=0` persists in the cart, appearing as a ghost entry.

## Steps to Reproduce

```python
from shop.cart import Cart

cart = Cart()
cart.add_item("APPLE", 1.50, 2)
cart.remove_item("APPLE", 2)          # removes all 2 units

print(cart.items())    # → [LineItem(sku='APPLE', unit_price=1.5, quantity=0)]
print(cart.subtotal()) # → 0.0  (subtotal happens to be correct, masking the bug)
```

## Expected Behavior

After removing all units of a SKU the cart must contain **no entry** for that SKU:

```python
assert cart.items() == []
assert cart.subtotal() == 0.0
```

## Actual Behavior

`cart.items()` returns `[LineItem(sku='APPLE', unit_price=1.5, quantity=0)]`.  
Callers iterating `items()` encounter a spurious zero-quantity line, which can
corrupt downstream logic (e.g. order-summary line counts, serialisation, UI display).

## Root Cause

[`shop/cart.py`](../shop/cart.py) — `remove_item()` decrements `quantity` but never
removes the entry when it reaches zero.

```python
# current (buggy)
self._items[sku].quantity -= quantity

# correct
self._items[sku].quantity -= quantity
if self._items[sku].quantity <= 0:
    del self._items[sku]
```

## Fix

Add the guard in `Cart.remove_item()` — single-file change in `shop/cart.py`.
