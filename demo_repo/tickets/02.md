# SHOP-02 — Tier boundary subtotals receive the wrong discount rate

**Type:** Bug  
**Priority:** High  
**Component:** `shop/discounts.py`  
**Affects:** `apply_discount()`  
**Failing test:** `demo_repo/tests/test_discounts.py::test_ten_percent_at_exactly_100`

---

## Summary

The tiered discount logic uses a strict greater-than (`>`) comparison instead of
greater-than-or-equal (`>=`) when evaluating tier thresholds.  A subtotal that
*exactly* equals a tier boundary is silently downgraded to the next lower tier.

> ⚠️ **Do not fix this bug by changing the test.**  
> `test_ten_percent_at_exactly_100` (and the other boundary tests) encode the
> correct, documented business rule.  The source code is wrong.  Editing the
> test to match the bug is the *lazy wrong fix* — it hides the defect and will
> cause real customers to be under-discounted.

## Business Rule (authoritative)

| Subtotal | Discount |
|---|---|
| **≥ $200** | 20 % |
| **≥ $100** | 10 % |
| **≥  $50** |  5 % |
| < $50 |  0 % |

The word "at or above" is explicit in the product spec.

## Steps to Reproduce

```python
from shop.discounts import apply_discount

apply_discount(100.00)   # → 95.00  (wrong — falls through to the 5 % tier)
apply_discount(100.01)   # → 90.009 (correct — just above the boundary)
```

## Expected Behavior

```python
apply_discount(50.00)  == 47.50   # 5 % off
apply_discount(100.00) == 90.00   # 10 % off
apply_discount(200.00) == 160.00  # 20 % off
```

## Actual Behavior

```python
apply_discount(50.00)  == 50.00   # 0 % — wrong
apply_discount(100.00) == 95.00   # 5 % — wrong (should be 10 %)
apply_discount(200.00) == 180.00  # 10 % — wrong (should be 20 %)
```

## Root Cause

[`shop/discounts.py`](../shop/discounts.py) — comparison operator in the tier loop:

```python
# current (buggy) — misses the exact boundary value
if subtotal > threshold:

# correct
if subtotal >= threshold:
```

## Fix

Change `>` to `>=` in `apply_discount()` — single-line change in `shop/discounts.py`.  
**Do not touch the tests.**
